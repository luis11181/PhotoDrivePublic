# Browser API contract (v1)

Base path: `/api/v1`. Success responses use `{ "successful": true, "data": ... }`; errors use `{ "successful": false, "error": { "title", "detail" } }`.

JSON controller responses use the shared `ApiRes` envelope. Controllers map `Result<T>` with `Match`; successful binary content/thumbnail responses remain raw streams, while their errors still use `ApiRes` (including malformed range requests).

Expected media outcomes have stable HTTP semantics: malformed/invalid input returns `400`, a catalog item or upload outside the caller's library returns `404`, and a valid request blocked by current state (protected folder, trashed item, expired restore, completed upload) returns `409`. Unexpected failures use the host's standard `500` envelope.

Browser authentication uses HttpOnly, SameSite=Strict cookies. The short-lived access JWT cookie is scoped to `/`; the rotating opaque refresh cookie is scoped only to `/api/v1/users/refresh-token`, and the database stores only its SHA-256 hash. Cookies are `Secure` whenever `Security:RequireHttps` is enabled; explicitly configured private-LAN HTTP mode uses non-Secure cookies so authentication can work without TLS. Sign-in and `GET /users/me` return `X-CSRF-Token` and establish its matching cookie; authenticated mutations and refresh must echo the header. `GET /users/csrf-token` bootstraps an anonymous request token when an expired browser session is being restored. Missing/invalid CSRF returns structured `400`. The API uses the custom API-only filter, not MVC/Razor antiforgery.

The Docker distribution serves the frontend and API from one origin. Credentialed CORS remains fail-closed for custom development or split-origin deployments: `Frontend:AllowedOrigins` accepts exact browser origins, while `Frontend:AllowedHttpHostsAnyPort` is reserved for explicitly trusted private HTTP hostnames. The matcher never accepts suffixes, paths, queries, user information, or wildcards, and it echoes an accepted origin rather than using credentialed `*`.

CORS is only one request gate. `AllowedHosts` validates the destination hostname; trusted-proxy processing establishes the canonical client address; the optional client IP/CIDR allowlist filters that address; and authentication, CSRF, authorization, and rate limiting then apply. See [Configuration](../docs/CONFIGURATION.md) for deployment examples and security implications.

Clients send `X-Correlation-ID`; the API returns/logs it. Never expose or log passwords, cookies/tokens, credentials, object keys, or content hashes.

### Private family sharing

Sharing v1 accepts only the `viewer` role and only non-disabled allowlisted human family accounts. A grant changes SQLite catalog authorization only: it never moves/copies an item or original. Folder grants inherit through the current owner hierarchy, so moving an item into or out of the subtree changes recipient access immediately. Recipients may browse, inspect, stream/download, thumbnail, and favorite; rename, move, trash/restore, upload/create, metadata retry, grant management, and reshare remain owner-only. Unauthorized item access returns `404`.

| Method and path                                    | Contract                                                                                                                                                                                                |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /shares?parentId=&cursor=&limit=&type=&sort=` | Without `parentId`, lists direct active grant roots in the virtual Shared with me view. With it, lists one accessible shared folder's live children. Uses the Files type/sort values and opaque cursor. |
| `GET /shares/recipients`                           | Safe display name/email directory of non-disabled allowlisted family recipients excluding the caller; service identities are excluded.                                                                  |
| `GET /shares/items/:itemId`                        | Owner-only direct grant list for one item.                                                                                                                                                              |
| `PUT /shares/items/:itemId/:recipientUserId`       | CSRF-protected `{ role: "viewer" }`; creates or refreshes a direct grant. Self-sharing, protected roots, trashed items, disabled/unknown recipients, and other roles are rejected.                      |
| `DELETE /shares/items/:itemId/:recipientUserId`    | CSRF-protected owner revocation. Inherited access disappears immediately unless another direct/ancestor grant still applies.                                                                            |

Trashing hides shared access and restoring makes the retained grant visible again. Revocation hides recipient favorite state without deleting it, so a later re-grant restores that private preference. The frontend can share one selected folder or several selected files/photos by calling the idempotent `PUT` endpoint sequentially and reporting success/failure counts; there is no batch sharing endpoint yet. Anonymous links and editor roles are not implemented. Files search offers an indexed Shared with me scope; the Shared browse route itself remains focused on navigation and disables its search field.

### Albums

Photo albums are library-owned SQLite collections of images/videos. The browser presents Albums as a child of Photos; API routes retain the concise `/albums` name. Membership never moves/copies a file or original, album deletion retains every file, and adding requires an active image/video in the same owner library. Moving a member into or out of Media does not remove its independent album membership. Member browse supports album-scoped name/tag search, media type, capture year, caller Favorites, and capture/newest-added sorting before opaque-cursor pagination. Owner tags remain private from album viewers. Covers remain derived catalog views: one or two active members use the newest member, while three or more use up to four newest active members as a mosaic. Trashed members are hidden and reappear after restore because trashing does not delete membership.

Album grants reuse private family `viewer` sharing. A viewer may browse the album, inspect/stream/thumbnail/download its current active members, and keep private favorites. Removing membership or revoking the album grant removes member access immediately unless another direct, folder, or album grant still authorizes the file. Shared albums appear in Albums rather than as roots in Shared with me.

### Sequential resumable upload

1. The browser durably checkpoints the selected file in a user-scoped IndexedDB queue. `POST /uploads` accepts `{ clientUploadId?, name, mimeType?, sizeBytes, parentId?, useDefaultMediaFolder, useDefaultDocumentsFolder, allowNameConflict }` and returns `{ id, chunkSizeBytes, receivedBytes }`. Repeating the same owned `clientUploadId` and immutable session facts idempotently returns that session, closing the create-response/browser-checkpoint crash window. An explicit parent is a catalog folder ID.
2. `GET /uploads/:id` returns owned authoritative `{ id, chunkSizeBytes, receivedBytes, sizeBytes, state }` progress. Another user's or unknown session is `404`.
3. `PATCH /uploads/:id` sends the next `application/octet-stream` chunk with `Content-Range: bytes start-end/total` and returns progress. Chunks are ordered and bounded by the server-provided size.
4. `POST /uploads/:id/complete` with `{ sha256, allowNameConflict }` verifies staged bytes, rechecks same-folder active-name conflicts under the completion mutation gate, conditionally stores the original, and commits blob/version/file/pending metadata rows. A late `409` retains the completed staging, so Keep both retries completion without retransmission. Successful completion is idempotent and returns `{ item, duplicateState: "none"|"active"|"trashed" }`; duplicate state is same-library catalog information, exposes no matching item/hash/storage identity, and means the new catalog item reused identical immutable original bytes.
5. `DELETE /uploads/:id` cancels an owned pending session and removes its staged bytes. Completed sessions cannot be cancelled.

`POST /uploads/name-conflicts` remains available for a batch preflight without exposing item IDs, but correctness does not depend on it: both session creation and completion enforce the explicit conflict policy. Keep both creates a second catalog item; it never replaces bytes or history.

Photos-root upload selects Media; Files is the Documents workspace, so Files-root uploads select Documents; explicit folder browse uses that folder. Photos visibility is then derived from that catalog location and the byte-detected media type. PutObject is used through 5 GiB and multipart above it. Private immutable object recovery metadata includes the first object-creating uploader's UUID and email, but neither value is exposed through the browser API or logs. A post-commit worker handles cache seeding, byte-based extraction, configured recovery-manifest creation, and staging cleanup. When recovery manifests are disabled, item metadata reports `recoveryManifestState: "disabled"`; enabling the strategy later backfills those manifests. Worker failure is reported through metadata state and never reverses upload success.

### Authenticated Takeout imports

All import endpoints require an authenticated family account and scope jobs/folders to that caller's library. Import mutations are CSRF protected.

| Method and path                                   | Contract                                                                                                                                                                                                                                                           |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /imports/options`                            | Returns the caller's active catalog destination folders as opaque IDs and display paths; it never lists server directories.                                                                                                                                        |
| `GET /imports`                                    | Latest 20 caller-owned jobs with destination, aggregate state, progress, warnings, and every terminal outcome count. Absolute source paths are omitted.                                                                                                            |
| `GET /imports/:id`                                | Aggregate status for one caller-owned job.                                                                                                                                                                                                                         |
| `GET /imports/:id/items?category=&cursor=&limit=` | Paginated item outcomes for `all`, `imported`, `skipped`, `duplicates`, `name_conflicts`, `warnings`, or `failed`. `skipped` combines identical-byte and same-name skips. Returns source-relative path/name, warning/outcome codes, sanitized error, and optional resulting/matched catalog file ID; never the absolute source root. |
| `POST /imports/google-takeout`                    | `{ sourcePath, destinationFolderId, nameConflictPolicy: "skip" \| "keep_both", skipIdenticalFiles: boolean }`; `skipIdenticalFiles` defaults to `true` and compares SHA-256 only within the caller's library. The endpoint validates any readable server-local extracted directory plus an active folder in that library, discovers deterministic item rows, returns `201`, and wakes the restart-safe worker. |
| `POST /imports/:id/retry`                         | Requeues only failed items while preserving imported/skipped terminal outcomes.                                                                                                                                                                                    |

The worker imports into the selected folder. Byte-detected images/videos appear under “All photos & videos,” and also in the default Photos projection when the selected destination is inside Media. Exact adjacent supplemental sidecars win, followed by one unique same-directory `title` match. Missing/malformed/mismatched/ambiguous sidecars are item warnings, not original failures. Google taken time is UTC and precedes EXIF; optional description/coordinates are exposed only by authenticated item details. All-zero Takeout location objects are missing values.

When `skipIdenticalFiles` is enabled, a same-library byte match is `duplicate_active` or `duplicate_trashed` and creates no catalog item. When disabled, identical bytes may create another catalog file while still reusing the immutable original. The job-wide selected-folder name policy applies independently before conditional original storage. Outcomes include imported new/reused original, both duplicate states, name conflict, source/destination changed, read/storage/catalog failure, plus sidecar warnings. No API response exposes hashes, S3 facts, or absolute source paths.

### Owner developer operations

The `/developer` page and these APIs are available in Development and Production, but every operation is Owner-authorized and every mutation is CSRF-protected. Its Owner health center derives one readable status from the authoritative backup checkpoint, cache coverage, current/last cache operation, and the latest explicit audit in the browser session, then links to the existing guarded actions. Responses expose aggregate facts and opaque IDs, never storage hashes, object keys, or local paths.

Cache builds use `/system/cache-builds`:

- `GET /system/cache-builds/options` returns configured/current original-cache bytes, free disk bytes, installation-wide catalog file and deduplicated-original storage totals, catalog media/original counts, and current thumbnail/original cache coverage.
- `POST /system/cache-builds/preview` accepts `{ keepOriginals }` and calculates missing thumbnail/original counts plus planned S3 download bytes without changing state. The Developer page uses this immediately before start rather than exposing a separate review workflow.
- `POST /system/cache-builds` starts durable missing-only work only when the submitted reviewed counts/bytes still match. Keeping originals defaults to `true`. Thumbnail-only work may still download an uncached original to private staging, creates the default grid thumbnail, and removes that temporary source.
- `GET /system/cache-builds` returns only the current/last aggregate operation. `POST /:id/cancel` cooperatively stops remaining items; `POST /:id/retry` requeues only failures. Only one installation-wide build can run, a new build replaces the prior terminal checkpoint, and its item leases survive process restarts.

- `POST /developer/maintenance/audit` HEAD-checks catalog-referenced originals, inventories versioned original/manifest storage, reports privacy-safe catalog/local-cache/versioned-storage totals, refreshes opaque inconsistency candidates, removes completed-upload staging remnants, and evicts only original-cache entries above its configured budget. It never deletes S3 originals/manifests or catalog data, and does not create a backup.
- `GET /developer/maintenance/backup-status` returns the timestamp and age of the last remotely verified backup plus `current`, `stale`, or `missing` status against the configured backup interval. It exposes no bucket, key, checksum, or catalog content.
- `GET /developer/maintenance/health` returns privacy-safe recovery and failure status: the durable backup failure streak, stale pending uploads, pending/stale/failed metadata, repeated background failures, free disk, cache pressure, and actionable issue codes. It never returns filenames, paths, hashes, storage keys, or exception text.
- `POST /developer/maintenance/backup` creates timestamp-matched SQLite-consistent catalog and Users snapshots, restore/integrity/foreign-key/reference-checks both plus catalog-to-Users UUID coverage, optionally writes portable BOM-free catalog and Users recovery exports when configured, uploads the complete enabled set to the dedicated backup bucket, and verifies remote size/checksums. A successful run advances the same remote-verification checkpoint used to decide whether startup needs a backup. It never inventories or deletes original storage, manifests, catalog data, or caches. The twice-daily schedule runs this backup operation only.
- `POST /developer/maintenance/cleanup` accepts selected opaque candidate IDs, their reviewed count and byte total, and `DELETE INCONSISTENCIES`. It rejects stale selections before backup work, then creates and remotely verifies a fresh catalog-and-Users backup; any backup failure blocks cleanup. It revalidates the selection and references immediately before permanently deleting only those selected exact unreferenced originals/manifests plus their rebuildable local derivatives, and verifies no object versions remain. It never clears Trash or affects unselected candidates, and returns the safety backup-set ID.

## Item semantics

Items use stable opaque IDs and expose `name`, `kind`, optional type/size/parent/capture facts, dates, favorite state, attached `{ id, name, color }` tag summaries, `localState`, `syncState`, thumbnail path, trash facts, optional system role/capabilities, and current `metadata`. Photos pagination uses opaque versioned directional keyset cursors; month-anchor cursors seek inclusively to the selected capture month, after which every non-empty page independently reports valid next and previous cursors whenever matching items exist in those directions. Photos and Search results also include a SQLite-only `catalogPath` so cards/details can show the one catalog file's location. Metadata includes state/attempts/privacy-safe error, detected MIME/format, dimensions/orientation, capture candidates, processed time, and manifest state. Raw EXIF, object keys, bucket names, and hashes are not returned.

Authenticated item details may additionally expose imported taken time, description, latitude/longitude, and optional altitude. Browse/search responses omit those richer imported values. `localState` is a cache hint, not durability. A committed upload/import can be durable while metadata remains pending/failed. Capture precedence is `user` (future) > imported metadata > EXIF original > EXIF digitized > embedded creation > filename > catalog ingest time. Filesystem timestamps are never used.

## Deferred contract

These are planned, not implemented: `GET /libraries/:id`, replacement/version history, custom album ordering/covers, editor/link sharing, album/metadata/OCR search, and pin/unpin. Specialized multi-item flows such as sharing and metadata retry still use their individual endpoints; favorite/move/trash/restore, tag assignment, and album membership have batch contracts.
